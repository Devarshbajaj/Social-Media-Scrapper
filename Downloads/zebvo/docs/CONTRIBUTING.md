# Contributing Guide

## How to Contribute

Thank you for interest in contributing! Here's how you can help:

### Getting Started

1. Fork the repository
2. Clone your fork
3. Create a feature branch
4. Make your changes
5. Submit a pull request

### Code Style

- Use semicolons
- Use const/let, avoid var
- Use arrow functions when appropriate
- Add comments for complex logic
- Keep functions small and focused

### Commit Messages

Use descriptive commit messages:
- `feat: Add new feature description`
- `fix: Fix bug description`
- `docs: Update documentation`
- `refactor: Refactor code section`
- `test: Add tests`

### Pull Request Process

1. Update documentation if needed
2. Add tests for new features
3. Ensure all tests pass
4. Update README if needed
5. Request review from maintainers

### Reporting Issues

- Check existing issues first
- Provide detailed description
- Include steps to reproduce
- Add error messages/screenshots
- Specify your environment

### Feature Requests

- Describe the feature
- Explain the use case
- Provide examples
- Discuss implementation approach

### Development Setup

See [SETUP.md](./SETUP.md) for development environment setup.

### Testing

```bash
cd backend
npm test

cd ../frontend
npm test
```

### Questions?

- Open an issue
- Join our Discord community
- Email: dev@socialscraper.dev

Thank you for contributing!
